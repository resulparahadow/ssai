# Scripts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn PPV sets into steps inside ordered, per-creator scripts (Text / Free / PPV steps) that load into the composer with one click and track per-fan progress.

**Architecture:** Rename `ppv_sets` → `script_steps` and `ppv_set_sends` → `script_step_sends` in place (ids and history survive), add a `scripts` table, and replace `PpvSetController` with `ScriptController`. The client's PPV rail becomes a Scripts rail; `ComposerState.ppv` becomes `step` and may hold a text-only step. Name labels and the `[bracket]` guard are pure client helpers.

**Tech Stack:** Laravel 13 / PHP 8.3, Pest, Inertia 2 + Vue 3 TS, Wayfinder (generated `resources/js/actions` + `resources/js/routes`, git-ignored, regenerated by the Vite plugin), node client checks in `tests/client/`.

**Spec:** `docs/superpowers/specs/2026-11-25-scripts-design.md` (builds on `docs/superpowers/specs/2026-11-08-ppv-sets-design.md`).

## Global Constraints

- Price is `0` or `$3–$200` with ≤2 decimals — reuse `App\Rules\PpvPrice` server-side and `isValidPpvPrice` client-side. A price needs media.
- ≤ 40 media per step (`ScriptController::MAX_MEDIA = 40`, used by `OnlyFansChatController::send`).
- A step needs text or media (both empty → 422).
- Reads: anyone assigned to the creator (`AuthorizesCreator`). Writes (scripts + steps CRUD/reorder): `can:manage-team` group. Marks: anyone assigned (spec open question 1, taken as "yes").
- Every lookup pinned to `{model}`'s `creator_model` (`withoutGlobalScopes()->where('creator_model', …)`), so another creator's id is a 404/422 even for an admin.
- JSON 422s via `validateJson` (routes are not under `api/*`).
- Explicit `$fillable` on every model. `Script` + `ScriptStep` use `CreatorAccessScope`; `ScriptStepSend` uses `BelongsToChatter`.
- Ledger: no message text. `script_step_id` is `nullOnDelete`; `step_title` snapshot written on every row.
- Thumb files stay at `storage/app/private/ppv-thumbs/{model}/{media}` (no file moves); only the route path changes to `scripts/thumb/{media}`.
- Static route segments (`order`, `steps`, `thumb`, `status`) registered above `{script}` / `{step}` wildcards; numeric wildcards use `whereNumber`.
- Never put step text in the generate `context` (it flips AGENT OVERRIDE).
- Engine and `legacy/` untouched.
- `npm run lint:check`, `npm run types:check`, `npm run format:check` (changed files), `php artisan test` must pass.

## Review Focus

1. **Migration on existing data** — sets from two creators, with sends, must come out as two "PPV sets" scripts with the same step ids, same order, and every send row still attached. Pinned by Task 1's migration test.
2. **Deleting a script with sent steps** — the confirm says how many steps; afterwards the ledger rows remain with `script_step_id = null` and `step_title` intact, and `status` doesn't return them. Pinned in Task 2.
3. **A text step sent with the chip removed** — must not write a ledger row; with the chip on, must write one even though there's no media or price. Pinned in Tasks 3 and 6.
4. **Names the fan must never see** — `{Fan Name}` for a fan named `u12345678`, or with no name and no fallback, must not produce "hey u12345678" or "hey ,". Pinned in Task 5.
5. **Bracket guard false positives** — a message with no `[` must send with no prompt; `[` without `]` must not prompt. Pinned in Task 5.
