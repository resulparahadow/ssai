# PPV Sets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Managers save creator-wide PPV sets (vault media + price + caption); chatters load one into the composer from a new right-rail PPV tab, have SSAI write a fan-specific caption, and send a real locked PPV.

**Architecture:** Two new tables (`ppv_sets`, `ppv_set_sends`) behind a `PpvSetController` on the existing `onlyfans/{model}` route family, read by any assigned user and written under `can:manage-team`. The chat controller's `send` lifts the PPV block (price 0 or 3–200, up to 40 vault ids) and writes a ledger row when a `ppvSetId` rides along; `generate` accepts `sender: 'ppv'` and skips the shared-state writes for it. On the client, `ComposerState.ppv` drives a PPV strip in `SsComposer`, a `SsPpvRail` tab in `Conversations.vue`, and `SsVaultGrid` gains a "Save as PPV set" bulk action.

**Tech Stack:** Laravel 13 / Pest · Inertia 2 + Vue 3 + TS · existing `OnlyFansService` proxy · Node engine sidecar (unchanged).

**Spec:** `docs/superpowers/specs/2026-11-08-ppv-sets-design.md`

## Global Constraints

- Price: `0` or `3.00 ≤ price ≤ 200.00`, max two decimals. Vendor rejects anything else.
- Media per set: 1–40 items, `type` ∈ `photo|video|gif|audio`, `id` = vault id string.
- Stored `thumb` only when its host ends with `onlyfans.com`; otherwise `null`. Verified live 2026-11-08: vault `files.thumb.url` is `cdn2.onlyfans.com` for photos and videos.
- No fan message text persisted. Ledger carries ids, price, time only.
- Every new nested key on `send`/`generate` payloads needs a validation rule or Laravel strips it.
- Models: explicit `$fillable`, never `$guarded`.
- `PUT ppv-sets/order` registered ABOVE `ppv-sets/{set}` routes.
- Writes gated by the existing `Route::middleware('can:manage-team')` group inside the `onlyfans/{model}` prefix; reads use `authorizeCreator` (chatter must be assigned).
- Pint, `npm run lint:check`, `npm run types:check`, `php artisan test` green at every commit.

## Review Focus

1. A set whose vault media was since deleted on OnlyFans: send must surface the vendor's error verbatim, not a generic failure, and the ledger must not be written (covered: Task 3 "vendor failure writes no ledger row").
2. Price typed as `20.5` or `3` or `0`: all valid; `2.99`, `200.01`, `19.999` → 422 before any vendor call (Task 3).
3. A chatter on creator A posting `ppvSetId` of creator B's set: 422, send still goes out without a ledger (Task 3).
4. Loading a set while a suggestion is on screen: confirm, then suggestion cleared, so Accept cannot send old text with new media (Task 6).
5. Caption generate for one fan must not change another chatter's AI Intel view of that fan or the fan's memory (Task 4).
